# Документация ZI-Ops

Руководство для версии **1.6.0.0**.

[Главная страница](README.md) · [История изменений](BeforVersion/PATCH_NOTES.md)

ZI-Ops управляет файлами сервера Rust через FTP/FTPS, отправляет команды через RCON, показывает публичный статус через Query и работает с картами RustMaps. Подключения настраиваются отдельно: для проверки плагинов нужен FTP, для серверных команд — RCON, для публичного статуса — Query.

## Первый запуск

1. Запустите `ZI-Ops.exe` и откройте «Настройки».
2. Перенесите данные подключения из панели своего хостинга. Заполняйте только те подключения, которыми планируете пользоваться.
3. Для файловых операций укажите базовую FTP-папку и нажмите «Проверить FTP и базовую папку».
4. Для команд откройте «RCON», подключитесь и нажмите «Проверить». В консоли должен появиться ответ на `status`.
5. Для Query укажите его порт и откройте вкладку «RCON»: статус появится в боковом блоке.
6. Нажмите «Сохранить настройки».

Перед первым вайпом или заменой плагинов сохраните резервную копию нужных файлов сервера. Стандартные пути в программе — примеры; проверьте их по своей структуре папок.

При запуске из исходников нужен Python с Tkinter и пакет для RCON:

```bash
python -m pip install websocket-client
python zi_ops.py
```

## Настройки подключения

### FTP / FTPS

| Поле | Что указать |
| --- | --- |
| Хост | Адрес FTP-сервера из панели хостинга. |
| Порт | FTP-порт, предоставленный хостингом. |
| Пользователь и пароль | Данные FTP-доступа. |
| Базовый путь | Папку, относительно которой программа будет искать файлы сервера. |
| FTPS | Включить, если хостинг требует защищённое FTP-подключение. |

Например, если базовый путь — `/server/`, а путь плагина — `oxide/plugins/Example.cs`, итоговый путь будет `/server/oxide/plugins/Example.cs`.

Указывайте пути относительно выбранной базовой папки, чтобы не повторять её в каждом поле. Проверка FTP подключается к серверу и проверяет доступ к базовой папке; файлы при этом не изменяются.

Поддерживается явный FTPS. Неявный FTPS на порту 990 не поддерживается.

### RCON

Укажите адрес сервера, **RCON-порт** и RCON-пароль. Игровой порт и RCON-порт могут различаться; берите значение из панели хостинга.

Программа использует WebRCON через WebSocket. Поле «Путь» оставьте пустым, если хостинг не сообщил отдельный путь подключения. SSL/TLS включайте для подключения по `wss://`.

После изменения адреса, порта или пароля отключите старое соединение и подключитесь снова. Некоторые хостинги ограничивают выполнение RCON-команд: это зависит от настроек сервера и предоставленных прав.

### Query

Укажите **Query-порт** из панели хостинга или значение `server.queryport`. Для Query используется UDP, пароль не нужен. Если адрес Query оставить пустым, программа возьмёт адрес из настроек RCON.

Не подставляйте игровой или RCON-порт вместо Query-порта. Даже у одного сервера все три значения могут быть разными.

## Вайп

Вкладка «Вайп» выполняет заданные файловые операции через FTP. Состав вайпа определяется вашими списками: удаление мира, данных игроков или данных плагинов зависит от выбранных путей.

### Списки удаления

- **Файлы для удаления** — по одному пути файла на строку.
- **Папки для очистки** — по одному пути папки на строку. Удаляется всё её содержимое, включая вложенные папки и файлы.

Списки можно загрузить из TXT, сохранить в TXT или сбросить к стандартным. Перед запуском проверьте каждую строку: содержимое папки, добавленной в список очистки, будет удалено целиком.

### Seed и размер карты

Если нужно изменить карту, включите запись нового seed в `server.cfg` и задайте размер карты. Для случайного значения включите «Случайный seed»; для конкретного — отключите его и введите свой seed.

Выберите локальный шаблон `server.cfg`, например предварительно скачанный с сервера. Кнопка «Проверить» открывает его содержимое. Программа подготавливает файл с новыми параметрами и загружает его как `server.cfg` в базовую FTP-папку; локальный шаблон сохраняется без изменений.

Если шаблон не выбран, seed копируется в буфер обмена, а `server.cfg` на сервер не загружается. Перенесите значение в настройки сервера самостоятельно.

Некоторые хостинги задают seed и размер карты в панели или параметрах запуска. В таком случае изменение `server.cfg` может не влиять на карту — значения нужно менять в панели хостинга.

### Запуск

1. Остановите сервер через панель хостинга перед удалением файлов мира.
2. Проверьте списки удаления и параметры карты.
3. Если используете рестарт через RCON, задайте таймер и сообщение. Эта функция требует доступного RCON-соединения; остановленный сервер через RCON запустить нельзя.
4. Нажмите «Запустить вайп».
5. В предпросмотре проверьте полные пути и список действий, затем нажмите «Выполнить».
6. Дождитесь результата в логе. После файлового вайпа запустите остановленный сервер через хостинг.

«Остановить» прерывает процесс после текущей операции. Уже удалённые файлы автоматически не восстанавливаются.

Кнопка «Важное» открывает памятку внутри программы: особенности параметров карты, RustMaps, ограничения RCON и обращение с файлом настроек.

## RustMaps

Получение случайного seed и генерация карты на RustMaps — разные действия. Для случайного числа API-ключ не нужен. Для обращения к сервису нужен ключ вашего аккаунта.

1. Войдите на [RustMaps](https://rustmaps.com).
2. Откройте [Dashboard](https://rustmaps.com/dashboard) и скопируйте API key.
3. Вставьте его в поле RustMaps API Key в «Настройках» и сохраните настройки.
4. Задайте seed и размер карты, затем используйте кнопку генерации на RustMaps.

Принятый запрос ещё не означает, что карта готова. Генерация занимает время; состояние и доступные лимиты смотрите в Dashboard своего аккаунта. Пока карта создаётся, не отправляйте тот же запрос повторно.

Проверка seed на RustMaps ищет карту с указанными seed и размером. Генерация в сервисе сама по себе не меняет настройки вашего игрового сервера.

## Судная ночь

Вкладка переключает набор плагинов и конфигураций через FTP. Вы сами выбираете файлы для начала и конца ночи. Программа меняет только точные пути из этого списка.

### Добавление файла

1. Нажмите «+ Добавить файл» и выберите файл на ПК.
2. Название берётся из имени выбранного файла. Через «Обзор...» можно выбрать другой файл.
3. В «Куда/откуда» укажите **папку** на сервере относительно базового FTP-пути, например `oxide/plugins/` или `oxide/config/`. Имя файла добавляется автоматически.
4. Отметьте нужный этап и сохраните список.

| Начало ночи | Конец ночи | При включении | При выключении |
| --- | --- | --- | --- |
| Да | Нет | Установить файл | Удалить файл |
| Нет | Да | Удалить файл | Установить файл |
| Да | Да | Установить файл | Установить файл |
| Нет | Нет | Не менять | Не менять |

Например, для `NightPlugin.cs` отметьте только начало, а для `DayPlugin.cs` — только конец. При включении установится ночной плагин и удалится дневной; при выключении произойдёт обратное.

### Переключение

Нажмите «Включить судную ночь» или «Выключить судную ночь». Перед выполнением программа показывает список установок и удалений. Проверьте его и нажмите «Выполнить».

Локальные файлы для установки должны оставаться по сохранённым путям. Если переместили их, выберите заново через «Обзор...». Один удалённый путь нельзя указывать несколько раз.

Перед изменениями программа сохраняет затрагиваемые серверные файлы в `JudgmentBackups` рядом с программой. При ошибке пытается вернуть исходное состояние; результат восстановления отображается в логе. Эти копии относятся к файлам текущей операции, а не ко всему серверу.

Кнопка «×» убирает строку из списка настройки; сама по себе она не удаляет файл с сервера.

## RCON

### Подключение и проверка

Нажмите «Подключиться», затем «Проверить». Проверка отправляет `status` и ожидает ответ до 10 секунд. В консоли отображаются название сервера, состояние и список игроков, если сервер вернул эти данные.

Успешное WebSocket-подключение само по себе ещё не подтверждает получение ответов на команды. При таймауте сначала проверьте RCON-порт и пароль.

### Быстрые команды и ручной ввод

Используйте готовые кнопки или введите команду вручную и нажмите «Отправить» либо Enter. Ответ сервера появляется в консоли. Остановка отправляет `quit`, рестарт — команду перезапуска.

При вводе части команды под полем появляются подсказки с описанием:

- стрелки вверх и вниз выбирают подсказку;
- Tab или щелчок подставляет команду в поле;
- Esc закрывает подсказки;
- Enter в поле ввода отправляет набранную команду.

Выбор подсказки сам по себе команду не отправляет. Список содержит стандартные команды; команды установленных плагинов можно вводить вручную.

### Быстрый вайп через RCON

Этот блок отправляет команды изменения seed и worldsize, сохранения и рестарта. **Файлы мира через FTP он не удаляет.** Для файлового вайпа используйте вкладку «Вайп».

Если карта задаётся параметрами запуска или панелью хостинга, проверьте значения там перед перезапуском.

## Query

Query находится справа от консоли на вкладке «RCON» и показывает название сервера, карту, число игроков, задержку запроса, версию и время последнего успешного обновления.

Запрос выполняется при открытии вкладки, затем повторяется с интервалом 10 секунд после завершения предыдущего запроса. При переходе на другую вкладку опрос прекращается; при возвращении данные запрашиваются снова.

Query работает отдельно от RCON: подключаться к RCON для публичного статуса не требуется. При ошибке сохраняются последние полученные данные с уведомлением, что обновить их не удалось. Смотрите время обновления, чтобы отличать свежие данные от предыдущих.

Этот блок не показывает CPU, RAM, FPS или сетевую нагрузку сервера.

## Плагины

### Проверка установленных версий

1. Укажите папку плагинов на сервере, например `oxide/plugins/`.
2. Добавьте источники версий вручную или загрузите готовый список.
3. Нажмите «Проверить версии».

Программа скачивает `.cs`-файлы во временную папку, читает название, автора и установленную версию из атрибута `Info`, затем сравнивает с версией по настроенной странице. После проверки временные файлы удаляются.

Если плагина нет в списке, программа предложит добавить ссылки и удалённый путь. Можно пропустить один плагин или все оставшиеся.

`?` означает, что последнюю версию определить не удалось. Это может быть пустая ссылка, недоступная страница, защита сайта или неподходящий формат версии; сам знак не означает, что плагин устарел.

Для временных ошибок предусмотрены повторные попытки — максимум 10 в соответствующих операциях проверки. Недоступная страница или неверная ссылка могут остаться неопределёнными и после повторов.

### Список источников

В блоке «Автообновление плагинов по URL» у каждой строки четыре поля:

| Поле | Назначение |
| --- | --- |
| Название | Название для сопоставления с плагином. Для готового списка удобно использовать имя файла без `.cs`. |
| URL скачивания (.cs) | Прямая ссылка на файл плагина для обновления. |
| Страница версии | Страница конкретного плагина, с которой определяется последняя версия. |
| Путь на сервере | Путь назначения, например `oxide/plugins/Example.cs`. |

Страница ресурса и ссылка скачивания могут различаться. Проверять версию можно и при пустом URL скачивания: такая строка не будет загружаться на сервер при обновлении.

В коде предусмотрена проверка источников uMod, GitHub Releases и страниц ресурсов, включая Codefling, Lone.Design, RustPlugin и Oxide Russia. Доступность проверки зависит от конкретной страницы и её формата. Для GitHub используется последний опубликованный Release. Указывайте страницу именно вашего плагина и автора: совпадение названия не гарантирует совпадение продукта.

### Загрузка готового списка

Нажмите «Загрузить список» и выберите JSON-файл. Загрузка заменяет текущие строки, поэтому при необходимости сначала сохраните свой список.

Формат одной записи:

```json
[
  {
    "name": "Example",
    "url": "https://example.org/plugins/Example.cs",
    "page": "https://example.org/plugins/example",
    "remote": "oxide/plugins/Example.cs"
  }
]
```

Ссылки в примере условные — замените их реальными. Верхний уровень файла — массив записей. «Сохранить список» экспортирует текущие строки в такой JSON. «Очистить» очищает список в программе, не удаляя серверные плагины.

### Обновление и кастомные плагины

«Обновить все» обрабатывает строки с заполненным URL скачивания, кроме отмеченных кастомных плагинов. Эта кнопка **не ограничивает обновление только строками со статусом «нужно обновить»**: проверьте весь список до запуска.

Программа скачивает файл, загружает его по заданному пути и удаляет временную локальную копию. Файл по существующему пути перезаписывается. Для предсказуемого имени назначения указывайте полный путь с именем `.cs`, а не только папку.

Если плагин изменён вручную, отметьте его в столбце «Кастомный»: массовое обновление будет его пропускать. Отметки сохраняются в настройках. Для таких плагинов также можно оставить URL скачивания пустым и использовать только проверку версии.

Сохраните собственные копии перед заменой плагинов. Скачивание платного ресурса или файла, требующего входа на сайт, может быть недоступно по обычной публичной ссылке.

### Сортировка таблицы

Нажимайте заголовки «Файл», «Название» и «Автор» для сортировки по тексту. Повторное нажатие меняет направление. Регистр не учитывается; порядок начинается со спецсимволов, затем идут цифры, русский алфавит, английский и остальные символы.

«Кастомный» сначала показывает отмеченные плагины. «Статус» — требующие обновления, актуальные, версии новее опубликованной и неизвестные. Повторный щелчок разворачивает порядок. Столбцы «Текущая» и «Последняя» не сортируются.

## Настройки и файлы программы

В «Настройках» можно переключить светлую и тёмную тему. Параметры сохраняются кнопкой «Сохранить настройки» и при обычном закрытии программы. «Загрузить настройки» импортирует выбранный JSON-файл.

| Файл или папка | Что хранится |
| --- | --- |
| `config.json` | Подключения, API-ключ, тема, списки вайпа, файлы судной ночи, источники плагинов и кастомные отметки. |
| JSON списка плагинов | Экспорт строк источников для загрузки через вкладку «Плагины». |
| `JudgmentBackups` | Резервные копии затронутых файлов операций судной ночи. |
| `BeforVersion/PATCH_NOTES.md` | Общая история версий и изменений программы. |

`config.json` находится рядом с программой. Пароли FTP/RCON и API-ключ записываются без шифрования. **Не публикуйте этот файл на GitHub и не передавайте вместе с программой.** При осознанной передаче настроек другому человеку вы передаёте и сохранённые данные доступа.

При переносе программы на другой ПК заново проверьте локальные пути к шаблону `server.cfg` и файлам судной ночи.

На вкладке «Поддержать автора» находятся ссылки автора и DonationAlerts. Пожертвования помогают продолжать разработку и выпускать обновления.

## Решение проблем

| Проблема | Что проверить |
| --- | --- |
| FTP не подключается | Адрес, порт, пользователя, пароль и необходимость FTPS. |
| FTP подключён, но файл не найден | Базовую папку и путь относительно неё. |
| FTP сообщает об отказе в доступе | Права пользователя на чтение, загрузку и удаление в нужной папке. |
| RCON не подключается | RCON-порт, пароль, WebSocket-путь и SSL/TLS. |
| RCON подключён, но ответ не приходит | Правильность RCON-порта, доступность команд и ограничения хостинга. |
| Query не отвечает | Отдельный Query-порт, адрес сервера и доступность UDP на хостинге. |
| Карта после рестарта прежняя | Откуда сервер получает seed и размер: `server.cfg`, панель или параметры запуска. |
| RustMaps отклоняет запрос | API-ключ, параметры карты и лимиты аккаунта. |
| Последняя версия плагина — `?` | Ссылку на конкретный ресурс, автора, доступность страницы и наличие версии на ней. |
| Вместо плагина скачивается HTML | Прямая ли это ссылка на `.cs`, требуется ли вход или покупка на сайте. |
