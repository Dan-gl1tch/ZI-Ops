# Руководство ZI-Ops 2.3.0.0

Это руководство относится к Kotlin / Compose Desktop для Windows. Android-версия ещё не собрана.

## Установка и сборка

Готовый переносимый файл — `dist/ZI-Ops.exe`. Запустите его без установки. Рядом не нужны ни конфиг, ни папки `app` и `runtime`, ни установленная Java. При первом запуске встроенные файлы распаковываются в `%LOCALAPPDATA%/ZI-Ops/portable/<хэш сборки>`, затем запускается приложение. Повторный запуск использует эту копию. Распаковка работает без сети; при новой сборке создаётся отдельный кэш. Настройки сохраняются в `%LOCALAPPDATA%/ZI-Ops/config.json`.

Сборка из исходников требует JDK 21 и интернета для первой загрузки Gradle и зависимостей. Переносимый запускатель компилируется штатным C#-компилятором .NET Framework Windows 10/11; отдельный .NET SDK не требуется.

- `build.bat` — один переносимый `dist/ZI-Ops.exe` с Java runtime внутри.
- `build.bat folder` — папка приложения с Java runtime в `build/compose/binaries/main/app/ZI-Ops`; при использовании этого режима переносите папку целиком.
- `build.bat test` — встроенные проверки, без действий на вашем сервере.
- `build.bat run` — запуск из исходников.
- `build.bat installer` — обычный EXE-установщик через Compose / jpackage / WiX.

`launcher/PortableLauncher.cs` и `scripts/build-portable.ps1` отвечают за переносимый EXE. Встроенный архив проверяется по SHA-256 перед распаковкой; временная папка заменяется готовой копией после успешной проверки. Запуски одной сборки синхронизируют распаковку. Старые кэши не удаляются автоматически, чтобы не мешать работающим версиям. Их можно удалить после закрытия соответствующих версий; основной `config.json` удалять для этого не нужно.

Gradle Wrapper включён в репозиторий. Версии зависимостей заданы в `build.gradle.kts`. Если используете собственный Gradle, укажите `GRADLE_HOME`. Для автоматизации можно задать `CI=1` (без паузы батника) и дополнительные параметры Gradle в `ZI_OPS_GRADLE_ARGS`. Закройте запущенную сборку перед её заменой.

## Вкладки

Порядок: **Вайп → Судная ночь → RCON → Консоль сервера → Плагины → Поддержать автора → Настройки**. Если всё не помещается по ширине, верхняя строка прокручивается. На вкладке «Вайп» есть кнопка «Важное» с пояснениями по картам и доступу к настройкам.

## Настройки и перенос

В Windows файл находится в `%LOCALAPPDATA%\ZI-Ops\config.json`. Настройки сохраняются кнопкой «Сохранить настройки» и при штатном закрытии окна. Сохранение выполняется через временный файл с заменой готового JSON.

При первом запуске, когда внутреннего файла ещё нет, программа ищет прежний `config.json` в рабочей папке и рядом с `ZI-Ops.exe`. Найденный файл переносится во внутреннее хранилище; исходник остаётся на месте. Если внутренние настройки уже существуют, автоматической перезаписи не будет.

- **Импорт настроек:** выберите JSON. Его содержимое загружается в программу; сохраните кнопкой или закройте окно штатно. Исходный импортируемый файл не меняется. Локальные пути в нём могут потребовать изменения на новом ПК.
- **Экспорт настроек:** выберите файл для копии текущих настроек, включая ещё не сохранённые изменения. Основной внутренний файл не меняется.

Экспорт содержит все сохранённые настройки, включая пароли и API-ключ. JSON не зашифрован. Не публикуйте его вместе с исходниками. Отметки кастомных плагинов, тема, списки и высоты изменяемых логов также входят в настройки.

### FTP / FTPS

Укажите хост, порт, пользователя, пароль и базовый путь из панели хостинга. Относительные пути операций добавляются к базовой папке: например `/server/` + `oxide/plugins/Example.cs`.

Кнопка «Проверить FTP и базовую папку» подключается без изменения файлов и показывает результат в отдельном окне: текущий путь и список содержимого. Пустая папка тоже допустима. FTPS — явный TLS; это не SFTP/SSH.

### RCON

Нужны хост, RCON-порт и пароль WebRCON. SSL/TLS включает `wss://`. Поле «Путь» обычно пустое; заполняйте по данным хостинга. После изменения подключения отключитесь и подключитесь заново на вкладке RCON.

### Query и RustMaps

Для публичного статуса нужен UDP Query-порт. Не заменяйте его игровым или RCON-портом. Во вкладке RCON сведения обновляются каждые 10 секунд, пока вкладка открыта. Для генерации карт укажите RustMaps API Key своего аккаунта.

### Производительность

Число исполнителей проверки сайтов выбирается автоматически в диапазоне 1–4. Разные сайты могут проверяться параллельно. К одному сайту запросы последовательные. Файловые операции через FTP последовательные; RCON и Query выполняются отдельно.

## Вайп

Списки задают, что удалять: «Файлы для удаления» — по одному файлу на строку, «Папки для очистки» — пути папок, содержимое которых очищается. Списки можно загрузить и сохранить отдельно. Проверьте все пути до запуска.

Если включена смена карты, задайте seed и размер. Локальный шаблон `server.cfg` читается без изменения оригинала; подготовленный файл загружается на сервер. Без выбранного шаблона seed копируется в буфер обмена. Некоторые хостинги используют параметры своей панели вместо `server.cfg`.

Остановите сервер через хостинг перед удалением мира, проверьте предпросмотр действий и подтвердите операцию. Не рассчитывайте на автоматическое восстановление удаляемых списков: заранее сделайте свою резервную копию. После вайпа запустите сервер через панель. Отдельная опция отправки restart требует работающего RCON и не запускает остановленный сервер.

Высоту лога можно менять перетаскиванием разделителя; она запоминается для этой вкладки.

## Судная ночь

Добавьте локальные файлы и пути назначения. «Начало ночи» и «Конец ночи» определяют, на каком этапе файл устанавливается; на противоположном этапе он удаляется. При обеих отметках файл устанавливается на обоих этапах, без отметок — не меняется. Действия показываются перед подтверждением. Заменяемые файлы копируются в локальные `backups` относительно рабочей папки.

## RCON и консоль сервера

Подключитесь на вкладке RCON. Быстрые кнопки отправляют серверные команды; ручное поле поддерживает несколько команд через `;;` вне кавычек. После отправки поле очищается. Подсказки сгруппированы: Rust, Oxide, Carbon. Доступны прокрутка, стрелки, Tab для выбора и Enter для отправки. Наличие подсказки не означает, что соответствующий загрузчик установлен на вашем сервере.

Ответы на команды показываются в RCON. Сообщения, которые сервер отправляет сам, находятся во вкладке «Консоль сервера». Поэтому регулярные сохранения, события и ошибки плагинов не должны заполнять ответ `status`. Приложение отображает такие сообщения, но не исправляет ошибки серверных плагинов.

Логи RCON и консоли сервера занимают оставшееся место вкладки; есть прокрутка. В RCON рядом находится панель Query.

## Плагины

1. Проверьте путь папки плагинов на сервере.
2. Задайте источники в нижнем списке: имя, прямая ссылка на `.cs`, при необходимости справочная страница и путь на сервере.
3. Нажмите «Проверить версии». Счётчик показывает обработанные файлы из общего числа, включая файлы с ошибкой чтения.
4. Поставьте отметку «Кастомный» для файлов с вашими изменениями.
5. Для обновления нажмите «Обновить все» и следите за логом.

Имя источника сопоставляется с именем файла без `.cs`. Текущая версия берётся из `Info` установленного файла, последняя — из `Info` по прямой ссылке. Имя плагина проверяется перед установкой. Поле HTML-страницы сохранено для совместимости списка, но в текущей реализации проверка использует `.cs`.

| Статус | Значение |
| --- | --- |
| Актуален | Версии совпадают. |
| Обновление | По ссылке доступна более новая версия. |
| Неизвестно | Нет источника, не прочитана версия или запрос завершился ошибкой. |
| Сверх последнего | Установленная версия новее доступной по ссылке. |

Нажатие на заголовок сортирует таблицу. Квадрат в колонке «Кастомный» переключает отметку; крестик означает, что она включена. Отметки сохраняются в настройках.

Некастомные плагины заменяются только более новой версией с резервной копией. Для кастомных новая версия сохраняется в `Custom/<версия>/<файл>.cs` относительно рабочей папки; на сервер автоматически не отправляется. Перенесите свои изменения и установите доработанный файл самостоятельно.

Запросы к одному хосту имеют общую очередь и интервал не менее трёх секунд. При HTTP 429 интервал увеличивается, учитывается `Retry-After`, выполняются до трёх повторов с паузами. Если сайт продолжает ограничивать доступ, версия останется неизвестной. Сайты с авторизацией или покупкой могут не отдавать файл по обычной ссылке.

Кнопки сохранения и загрузки списка работают с отдельным JSON источников. Они не заменяют импорт/экспорт всех настроек. Высоту лога вкладки можно менять отдельно.

## Архив и структура проекта

`BeforVersion` содержит историю Python-версии и не используется для сборки Kotlin. Новый код — `src/main/kotlin/ziops/`, значки — `src/main/resources/`, генератор значка — `scripts/generate_icon.ps1`. Общая история Kotlin- и Python-версий находится в [BeforVersion/PATCH_NOTES.md](BeforVersion/PATCH_NOTES.md). Отдельного патчноута в корне нет.

## Очистка настроек

Создайте файл `empty-settings.json` с содержимым:

```json
{}
```

В «Настройках» нажмите «Импорт настроек», выберите этот файл, затем «Сохранить настройки» и перезапустите программу. Импорт заменяет текущие настройки пустым объектом. После перезапуска применяются начальные значения программы; данные доступа придётся ввести заново. Активное соединение RCON само по себе импортом не отключается, поэтому перезапуск нужен и для закрытия прежнего подключения.

Импорт не удаляет файлы сервера, локальные резервные копии, папку `Custom` или распакованный runtime. При необходимости сначала экспортируйте текущие настройки.

## Чистый комплект исходников

Результаты сборки `build/` и `dist/`, кэши `.gradle/` и `.kotlin/` не нужны для хранения в Git: батник создаст их заново. Значок берётся из `src/main/resources/ZI-Ops.ico`; копия в корне не требуется. Архив `BeforVersion` сохранён, а все изменения текущей версии дописаны в его общий патчноут.

## Правило версий

Используется формат **язык.функционал.код.визуал** — всегда четыре числа.

- Первое меняется при смене языка реализации (Python — 1, Kotlin — 2).
- Второе растёт при добавлении возможностей приложения.
- Третье растёт при исправлениях и доработках кода.
- Четвёртое растёт при изменениях интерфейса: размеров, отступов, значков, цветов и расположения элементов.

При повышении старшего разряда младшие обнуляются. Например, `2.3.0.0` → `2.3.0.1` после изменения только визуала; `2.3.0.1` → `2.3.1.0` после доработки кода; `2.3.1.4` → `2.4.0.0` после новой функции. Сделанные до обнуления визуальные изменения сохраняются в истории.

Текущий номер `2.3.0.0` учитывает Kotlin и три добавленные возможности: отдельную консоль сервера, экспорт настроек и переносимый EXE. Ранее использованные трёхчастные номера `2.0.8` и `2.0.9` были ошибочными. Полный номер хранится в одном файле `src/main/resources/app-version.properties`; интерфейс, HTTP-запросы и упаковка переносимого EXE читают его оттуда.
