# ZI-Ops — Zombie Island Operations

![Значок ZI-Ops](src/main/resources/zi-ops.png)

Текущая версия: **2.3.0.0 · Kotlin / Compose Desktop · Windows**.

ZI-Ops объединяет файловые операции FTP/FTPS, WebRCON, Query и работу с картами RustMaps для администрирования сервера Rust. Интерфейс перенесён с Python на Kotlin с сохранением привычных вкладок. Android пока не поддерживается: адаптация запланирована отдельно.

## Возможности

- **Вайп:** списки файлов для удаления и папок для очистки, новый seed и размер карты, подготовка `server.cfg` из локального шаблона, предварительный просмотр операций.
- **Судная ночь:** установка и удаление указанных файлов отдельно для начала и конца ночи; резервные копии заменяемых файлов.
- **RCON:** быстрые команды, пакетный ввод через `;;`, подсказки по группам Rust → Oxide → Carbon, публичный статус Query.
- **Консоль сервера:** отдельная вкладка для серверных сообщений. Ответы на ваши команды остаются в RCON.
- **Плагины:** таблица установленных версий, счётчик проверенных файлов, сортировка, отметки кастомных плагинов и обновление по вашим прямым ссылкам на `.cs`.
- **Настройки:** светлая и тёмная темы, проверка FTP с результатом в отдельном окне, импорт и экспорт JSON.
- **RustMaps:** генерация карты с API-ключом вашего аккаунта.

Настройки автоматически сохраняются в `%LOCALAPPDATA%\ZI-Ops\config.json`. Держать JSON рядом с EXE не требуется. Если внутренних настроек ещё нет, программа переносит старый `config.json` из рабочей папки или папки приложения. Старый файл сохраняется. При наличии внутренних настроек используйте «Импорт настроек».

## Начало работы

1. Запустите один файл `ZI-Ops.exe`. Установка и отдельная Java не требуются. При первом запуске он распакует встроенные файлы в данные пользователя, затем откроет программу.
2. Откройте последнюю вкладку «Настройки» и задайте параметры FTP, RCON и Query из панели хостинга. Это разные подключения, их порты могут отличаться.
3. Нажмите «Проверить FTP и базовую папку». Подключитесь к RCON на его вкладке.
4. Сохраните настройки. Для переноса на другой ПК используйте «Экспорт настроек» и затем «Импорт настроек».

Перед вайпом проверьте пути и сохраните нужные данные. Если seed и размер карты задаются хостингом, меняйте их в панели хостинга.

## Сборка Windows

Нужен **JDK 21** с инструментом `jpackage`; `JAVA_HOME` должен указывать на установленный JDK. Для первой сборки требуется интернет. Python и PyInstaller не нужны.

```bat
build.bat
```

Батник использует Gradle Wrapper 8.14.3 (или Gradle из `GRADLE_HOME`), собирает приложение с Java runtime и упаковывает всё в один файл:

```text
dist/ZI-Ops.exe
```

Этот EXE можно перенести отдельно. При первом запуске приложение распаковывается в `%LOCALAPPDATA%/ZI-Ops/portable/<хэш сборки>`. Дальше используется готовая копия; интернет для распаковки не нужен. Настройки хранятся отдельно в прежнем месте. Более старые копии кэша не удаляются автоматически, чтобы не мешать запущенной версии.

Для упаковки используется штатный компилятор .NET Framework из Windows 10/11; отдельный .NET SDK не нужен. Перед пересборкой закройте приложение и переносимый EXE. `dist/` и промежуточный `build/` исключены из Git.

Другие режимы:

```bat
build.bat folder
build.bat test
build.bat run
build.bat installer
```

`folder` собирает обычную папку в `build/compose/binaries/main/app/ZI-Ops` (переносить целиком); `test` запускает встроенные проверки без подключения к вашему серверу; `run` запускает из исходников; `installer` собирает Windows-установщик в `build/compose/binaries/main/exe`. Для установщика нужны инструменты WiX, которыми управляет задача упаковки Compose; первая загрузка требует сети.

## Проверка плагинов

Источник — прямая ссылка на `.cs`, возвращающая файл с атрибутом `Info`. Проверка сравнивает версию из скачанного файла с установленной. Поле «Страница версии» сохранено в списке источников, но текущая Kotlin-версия не извлекает версию из HTML-страницы.

Статусы: **Актуален**, **Обновление**, **Неизвестно**, **Сверх последнего**. Последний означает, что установленная версия новее доступной по ссылке. «Неизвестно» означает отсутствие подходящего источника или ошибку определения версии — подробности смотрите в логе.

Запросы к одному сайту идут последовательно с паузой. При HTTP 429 выполняются до трёх повторов с увеличением паузы и учётом `Retry-After`. Ограничения самого сайта это не отменяет. Проверки разных сайтов могут выполняться параллельно.

Отметка «Кастомный» защищает доработанный плагин от автоматической замены: новая версия сохраняется в `Custom/<версия>/` относительно рабочей папки, для переноса ваших изменений вручную. Другие плагины обновляются только при наличии более новой версии; перед заменой создаётся резервная копия.

## Состав репозитория и сброс настроек

Для сборки нужны `src/`, `launcher/`, `gradle/`, `scripts/build-portable.ps1`, `build.bat`, `build.gradle.kts`, `settings.gradle.kts`, `gradle.properties` и Gradle Wrapper (`gradlew`, `gradlew.bat`). Ресурсы значка находятся в `src/main/resources`; `scripts/generate_icon.ps1` позволяет их пересоздать. README, руководство, лицензия и `BeforVersion` сохраняются как документация и архив.

Папки `build/`, `dist/`, `.gradle/` и `.kotlin/` создаются при сборке, исключены из Git и не входят в исходный комплект. Их можно удалить после закрытия работающей сборки. Готовый переносимый EXE распространяйте отдельно от репозитория.

Чтобы очистить настройки, импортируйте JSON с содержимым `{}` и нажмите «Сохранить настройки», затем перезапустите программу. Сначала можно экспортировать текущие настройки для восстановления.

## Правило версий

Используется формат **язык.функционал.код.визуал** — всегда четыре числа.

- Первое меняется при смене языка реализации (Python — 1, Kotlin — 2).
- Второе растёт при добавлении возможностей приложения.
- Третье растёт при исправлениях и доработках кода.
- Четвёртое растёт при изменениях интерфейса: размеров, отступов, значков, цветов и расположения элементов.

При повышении старшего разряда младшие обнуляются. Например, `2.3.0.0` → `2.3.0.1` после изменения только визуала; `2.3.0.1` → `2.3.1.0` после доработки кода; `2.3.1.4` → `2.4.0.0` после новой функции. Сделанные до обнуления визуальные изменения сохраняются в истории.

Текущий номер `2.3.0.0` учитывает Kotlin и три добавленные возможности: отдельную консоль сервера, экспорт настроек и переносимый EXE. Ранее использованные трёхчастные номера `2.0.8` и `2.0.9` были ошибочными. Полный номер хранится в одном файле `src/main/resources/app-version.properties`; интерфейс, HTTP-запросы и упаковка переносимого EXE читают его оттуда.
