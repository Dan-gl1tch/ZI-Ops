# История изменений ZI-Ops

## 1.5.32.0
- Улучшена проверка версий вне uMod: JSON-LD softwareVersion/version карточки плагина (Codefling, XenForo/RustPlugin), поля версии и таблицы товара, заголовок текущего ресурса.
- Убран поиск произвольных v-номеров в описаниях других сайтов, который мог принять версию зависимости или комментария за актуальную версию плагина.
- Проверены реальные страницы Skills на Codefling и RustPlugin: обе вернули 2.2.9. Доступ к Lone Design не подтверждён: сайт ответил 403; универсальное чтение версии применяется, когда страница доступна и содержит поддерживаемые поля.
- Максимум попыток скачивания плагина по FTP увеличен с 3 до 10 с переподключением при временных ошибках канала.
- Для запросов версий добавлено до 10 попыток при сетевых ошибках, HTTP 408/429/5xx, с паузами и учётом Retry-After. Запросы к uMod разделяются минимум одной секундой. HTTP 403/404 не повторяются автоматически на том же endpoint; существующие альтернативные источники uMod сохранены.
- В логе отдельно объясняются отсутствие ссылки страницы версии и невозможность прочитать Info. Страница проверяется даже если установленная версия неизвестна; сопоставление учитывает имя файла и название плагина.
- Для проверок других сайтов нужны ссылки на конкретные карточки в Страница версии. Ссылки конфигурации автоматически не заменяются: одинаковое название не гарантирует совпадение плагина/автора.
- Проверены разбор реальных страниц и защита от случайных версий, успех HTTP/FTP на 7-й попытке, предел в 10 попыток и обработка 403 без повторов.
- Версия программы и zi_ops_version.txt синхронизированы.

## 1.5.31.3
- Убран диагностический RAW-вывод RCON: консоль показывает отправленную команду и обычный ответ сервера без дублирования JSON.
- Сохранены расширенный разбор ответов и ожидание 10 секунд. Текстовый ответ без JSON выводится как обычный ответ.
- Версии программы и файла сборки синхронизированы.

## 1.5.31.2
- Добавлен RAW-вывод каждого полученного WebSocket-сообщения до разбора JSON и проверки ID: в Проверить, ручных/быстрых командах и смене карты через RCON.
- Ответы не обрезаются. Поддержаны строковый Identifier, регистр имён полей, массивы, вложенные data/payload/response и бинарные UTF-8 сообщения. Простой текст выводится без требования JSON.
- Различаются отсутствие любых сообщений, полученные сообщения без совпадения ID и закрытие соединения. Отсутствие ответа не выдаётся за успешное выполнение команды.
- Ожидание ответа увеличено до 10 секунд. После чтения восстанавливается исходный таймаут сокета.
- Пройдены 10 тестовых сценариев разбора/RAW-вывода. Устранение отсутствия ответов на реальном сервере пока не подтверждено; RAW-вывод предназначен для диагностики.

## 1.5.31.1
- Обработчик соединения/ответов RustRCON возвращён точно к реализации 1.5.30.0 после сообщения об отсутствии ответов в новой версии.
- Кнопка Проверить снова использует прежний отдельный обработчик команды status; вывод ответа больше не ограничен 500 символами.
- Быстрые и ручные команды ожидают ответ через восстановленный обработчик, без дополнительного callback.
- Предпросмотр вайпа/судной ночи и проверка FTP сохранены.
- Проверены синтаксис, точное совпадение класса RCON с 1.5.30.0 и ответы проверки/быстрых команд на имитации WebSocket. Исправление на реальном подключении пользователя ещё не подтверждено.

## 1.5.31.0
- Перед вайпом и переключением Судной ночи добавлен предпросмотр внутри вкладки: точные пути удаления, очистки папок и установки, настройки карты и рестарта. Операция запускается только кнопкой Выполнить; Отмена не выполняет операции.
- Для вайпа случайный seed выбирается до подтверждения и совпадает с показанным значением. Некорректные пути и отсутствующий указанный шаблон блокируют предпросмотр.
- В Настройки добавлена проверка FTP: подключение, открытие базовой папки и показ её фактического пути и содержимого. Проверка не меняет файлы сервера.
- Быстрые и ручные команды RCON теперь ждут и показывают полный ответ вместо сообщения только об отправке. Проверить использует тот же обработчик; сообщения сервера с другими идентификаторами также выводятся.
- Блок смены карты через RCON показывает каждую отправленную команду и её ответ. Таймаут ожидания и ответ без текста обозначаются отдельно.
- Предпросмотр и проверка FTP поддерживают обе темы. Закрытая панель проверки не получает отложенные записи в уничтоженное поле.
- Прошли 8 проверок с имитацией FTP/RCON и скрытым интерфейсом Tk: предпросмотр, отмена, подтверждение неизменного списка, неправильные пути, чтение FTP, темы, длинные ответы и таймаут RCON. Реальный сервер не использовался, EXE не собирался.
- Версия программы и zi_ops_version.txt синхронизированы.

## 1.5.30.0
- В Настройки добавлена кнопка переключения светлой и тёмной темы.
- Текущая синяя палитра используется как тёмная; светлая тема получила светлый фон, тёмный текст и контрастные цвета статусов.
- Оформление переключается сразу для вкладок, таблиц, полей, логов, подсказок и встроенных памяток; новые элементы создаются в выбранной теме.
- Выбор сохраняется в поле theme файла config.json и восстанавливается при запуске. Конфиги без поля theme используют тёмную тему.
- Проверены обе темы, переключение туда и обратно, цвета логов и тегов таблицы, новые элементы, подсказки, сохранение и восстановление темы при запуске в скрытом интерфейсе Tk.
- Версия программы и zi_ops_version.txt синхронизированы; EXE не собирался.

## 1.5.29.0
- Вкладка Судная ночь переведена на настраиваемый список файлов: Обзор, имя из выбранного файла, папка на сервере, галочки Начало/Конец и удаление записи из списка.
- Включение устанавливает отмеченные для начала файлы и удаляет отмеченные только для конца; выключение выполняет обратное. Две галочки устанавливают файл на обоих этапах, без галочек файл не затрагивается.
- Операции ограничены точными путями активных записей. Папки не очищаются, другие плагины не удаляются; дубли путей и небезопасные пути блокируются.
- Все локальные файлы для установки проверяются и читаются до изменения сервера. Затрагиваемые серверные файлы резервируются в JudgmentBackups рядом с программой, с manifest.json.
- Входящие файлы загружаются и проверяются до удаления противоположного набора. При ошибке программа пытается восстановить прежние файлы; если FTP недоступен, сообщает о необходимости ручного восстановления из резервной копии.
- Новый список сохраняется в config.json. Старые поля сохранены в judgment_legacy, но не исполняются автоматически: после обновления нужно добавить файлы в новый список вручную.
- Версия программы и zi_ops_version.txt синхронизированы.
- Проверены 17 сценариев на имитации FTP и запуск интерфейса Tk, значения галочек, сохранение/загрузка списка и сохранность старых настроек. Реальный сервер и EXE не запускались.
